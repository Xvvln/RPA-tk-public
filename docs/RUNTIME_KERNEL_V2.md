# 运行时内核 V2 设计

## 目标

本设计解决两类系统性问题：

1. 多窗口环境下，TikTok 主窗口、助手悬浮窗、输入法和系统窗口互相覆盖，导致前台状态误判；
2. 点赞、收藏、评论、关注、Repost 和不感兴趣已经执行，但视频记录尚未提交，导致运行摘要无法准确表达外部副作用。

V2 不以新增 TikTok 资源 ID 为主要稳定手段。页面识别继续使用页面契约，运行时增加窗口仲裁、稳定采样和动作事务账本。

## 参考原则

- Android `AccessibilityWindowInfo` 的 `active`、`focused`、`type`、`layer` 是不同信号，不能用遍历顺序覆盖成单一前台值。
- UI 稳定表示连续采样中无关键结构变化，不等同于后台任务完全空闲。
- 控件查找、动作执行、动作确认是三个阶段；找到候选控件不等于动作成功。
- 外部写操作只尝试一次。结果不明确时停止，不重复点击。

## 1. 窗口观察模型

每次快照保存全部可访问窗口：

- `window_id`
- `package`
- `type`
- `layer`
- `active`
- `focused`
- `accessibility_focused`
- `bounds`
- `root_available`

`WindowArbiter` 使用以下优先级生成 `ForegroundDecision`：

1. 目标包获得输入焦点的应用窗口；
2. 目标包 active 的应用窗口；
3. 目标包应用窗口仍存在，且更高层窗口仅为本应用悬浮窗、输入法或系统覆盖层；
4. 获得输入焦点的其他应用窗口；
5. active 的其他应用窗口；
6. 无法形成充分证据时返回 `UNKNOWN`。

本应用窗口永远不能作为 TikTok 离开前台的直接证据。输入法和系统覆盖层保留在快照中，供弹窗/键盘契约识别，但不替换底层目标应用。

`ForegroundDecision` 必须包含：

- 选定包名；
- 是否确认目标包在前台；
- 是否确认其他应用在前台；
- 置信度；
- 决策来源和证据。

## 2. 稳定采样

页面安全判断仍要求两次连续高置信度快照。对于 `tiktok_not_foreground` 这类易受窗口焦点瞬变影响的阻断，只有连续两次均成立才升级为阻断；单次出现记为瞬态证据并返回 `UNKNOWN`。

页面迁移必须同时满足：

- 页面契约成立；
- 窗口仲裁允许操作目标包；
- 连续采样稳定；
- 迁移符合刚执行的动作。

## 3. 动作事务账本

每个真实外部动作使用独立事务：

```text
PREPARED -> ATTEMPTED -> VERIFIED -> COMMITTED
                      \-> UNKNOWN
```

- `PREPARED`：控件、页面和视频身份已经解析，尚未触发写操作；
- `ATTEMPTED`：在点击前同步落盘，保证进程在点击附近崩溃时不会自动重试；
- `VERIFIED`：TikTok 页面提供了动作成功的反向证据；
- `COMMITTED`：计入当前运行汇总和全局幂等索引；
- `UNKNOWN`：动作可能已经发生，但结果无法确认，后续运行不得自动重试同一幂等键。

幂等键由以下内容的哈希组成：

- 动作类型；
- 视频身份指纹；
- 动作载荷，例如评论文案哈希。

全局账本只保存哈希和状态，不保存视频正文或评论明文。单次运行的 `actions.jsonl` 保存必要诊断证据。

若视频作者或简介不足以形成稳定身份，本条视频允许继续浏览，但跳过外部写操作并记录 `identity_unresolved`。

### 3.1 写操作执行契约

TikTok 自定义控件返回 `ACTION_CLICK=true` 只能证明无障碍请求被接收，不是页面已产生变化的证据。
因此所有已解析的 TikTok 自定义操作必须经过同一契约：

1. 执行前从最新快照重新解析语义角色；
2. 要求窗口、包名、控件类型、资源身份和几何位置与已捕获目标一致；
3. 拒绝相邻操作栏控件、离屏 ViewPager 节点和其他窗口的同 ID 节点；
4. 只派发一次真实坐标手势，不先调用 `ACTION_CLICK`，也不在结果未知时补点；
5. 动作后同时校验当前视频身份、页面状态和动作特有的反向证据。

收藏验证使用绑定坐标的图标颜色前后变化，而不是只判断某一帧是否“像黄色”。
点赞、关注、评论、Repost 和不感兴趣也使用同一个手势调度入口，各自保留独立的结果契约。

### 3.2 视频页面与来源上下文解耦

TikTok 的首页推荐视频和搜索结果详情都使用全屏播放器，因此 `PageState.FEED` 只表示
“当前是可浏览的视频表面”，不能证明内容来自推荐首页。运行内核必须并行维护来源上下文：

- `RECOMMENDATION_HOME`：顶部“推荐 / For You”页签与底部“首页 / Home”导航同时可见、同窗，
  且连续两次快照一致；
- `SEARCH_DETAIL`：顶部返回、顶部搜索或底部评论输入框、至少两个视频操作控件组成联合契约，
  且连续两次快照一致；
- `UNKNOWN`：证据缺失、冲突或跨快照变化时停止，不猜测来源。

搜索阶段结束不能以 `PageState.FEED` 作为“已回首页”的成功条件。必须逐级退出搜索详情、
搜索结果和搜索输入页，并在推荐首页契约通过后，才允许把后续视频记录为 `source=feed`。

### 3.3 Repost 幂等状态契约

打开分享面板后，Repost 必须先进入只读三态判断：

- `AVAILABLE`：存在位于分享操作区的“转发 / Repost”可点击入口；
- `ALREADY_REPOSTED`：存在“删除转发 / 取消转发 / Undo repost”入口，表示目标状态此前已完成；
- `UNKNOWN`：两类入口同时存在、均不存在或页面证据不足。

`ALREADY_REPOSTED` 只能关闭面板并记录 `already_reposted`，不得点击删除入口，也不计入本次
新转发数。`AVAILABLE` 执行一次转发后，必须重新打开面板并观察到 `ALREADY_REPOSTED`，同时
确认底层仍为同一视频，才允许提交动作事务。`UNKNOWN` 停止操作，不重试、不猜测。

## 4. 汇总语义

运行汇总同时表达：

- `videos_seen`：完整完成观察和工作流的视频数；
- 各类 `action_counts`：已经 `COMMITTED` 的真实动作数；
- `external_actions_committed`：真实外部动作总数；
- `partial_video_actions`：本次运行存在外部动作，但相关视频没有完成提交。

历史 UI 不得再用“0 条视频”暗示“没有执行操作”。

## 5. 测试分层

### JVM 单元测试

- 窗口列表任意顺序不影响仲裁结果；
- 自家悬浮窗和输入法不能覆盖 TikTok；
- 其他应用真正获得焦点时能稳定判离；
- 单次前台瞬变不升级为阻断；
- 动作事务状态机不允许重复尝试；
- 汇总只统计 `COMMITTED` 动作。

### 黄金快照回放

- 回放历史 blocker 快照时校验页面、窗口决策和预期阻断；
- 不再只检查“能否找到候选控件”。

### Android instrumentation

- 使用当前稳定版 AndroidX Test 和 UI Automator；
- 验证主页冷启动、悬浮窗存在时目标应用窗口选择、通知及历史页面；
- instrumentation 不执行 TikTok 社交写操作。
- 持久使用的真机不得直接运行会卸载目标包的 Gradle `connected*AndroidTest` 生命周期；
  应使用 `adb install -r` 安装目标/测试 APK、`am instrument` 运行，再只卸载测试 APK，
  并在前后校验应用数据目录、配置摘要和无障碍绑定未变化。

### 真机受控测试

- 先验证启动、暂停、停止、人工中断和快照证据；
- 真实写操作仅使用专用测试账号、单视频、单动作，并逐类验收；
- 任何 `UNKNOWN` 都视为发布阻断，不通过重复点击消除。

## 6. 发布门禁

发布版本必须同时满足：

- 干净构建、单元测试、Lint、instrumentation 全部通过；
- 历史黄金快照无前台仲裁回归；
- 真机悬浮窗存在时不再产生虚假的 `tiktok_not_foreground`；
- 运行摘要与 `actions.jsonl` 可逐项核对；
- APK 记录源码版本、配置 schema 和测试报告，禁止用未追踪构建覆盖已安装版本。
