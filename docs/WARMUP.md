# RPA-TT 自动化养号 · 功能与流程

> 版本：0.5  
> 日期：2026-07-22  
> 形态：**Android 本机 App + 悬浮窗**  
> 部署：**无服务端**，一切只在当前手机本地完成  

---

## 1. 总体思路（先讲清楚）

### 1.1 产品一句话

装在**这一台 Android 手机**上的 App：用户已手动登录 TikTok 后，用**无障碍**模拟真人浏览；用**悬浮窗**在 TikTok 上层启停；配置、日志、汇总**全部写在本机**，不上传、不连自建后端。

### 1.2 三条铁律

| 铁律 | 含义 |
|------|------|
| 纯本机 | 无账号系统、无任务下发服务器、无远程控制；最多用系统通知和本地文件 |
| 人先机后 | 登录、验证码、敏感弹窗一律人处理；机器只做浏览与轻互动 |
| 模块即授权 | 赞/藏/评/关等模块关闭时绝不执行；开启后仍受概率、相关性条件和会话上限约束 |

### 1.3 为什么这样拆

```text
用户看到的
  ├─ 主界面：权限、配置、历史（在本 App 内）
  └─ 悬浮窗：跑任务时叠在 TikTok 上点开始/暂停/停止

真正干活的
  ├─ 无障碍服务：读界面、点击、滑动（本机系统能力）
  ├─ 养号引擎：按「固定骨架 + 方案动作顺序」推进状态机（本机内存 + 本地配置）
  └─ 前台服务：跑的时候常驻通知，降低被杀概率（仍是本机）

落盘
  └─ App 私有目录：配置 / 每次任务日志 / summary（不离开手机）
```

**不做的事：** 注册登录打码、清数据切号、发帖私信、批量营销、云端调度、多机协同服务器。

| 存储 | 本机私有目录 | 方案、日志、汇总 |

## 3. 养号流程（固定骨架 + 可编排动作）

会话阶段和安全边界固定；每条视频内的互动动作由方案给出顺序。轻量、常规、积极使用内置顺序，自定义方案允许用户重排已启用动作。

### 3.1 总览

```text
[准备] → [开场检查] → [兴趣搜索段] → [推荐流主段] → [收尾汇总]
              │              │              │
              │              └─ 可跳过（配置 search.enabled=false）
              │
              └─ 任意时刻：暂停 / 停止 / 阻断停机 / 可逆恢复
```

### 3.2 阶段 0：准备（人做，机器只检查）

用户在第一次使用时完成；之后每次开跑前引擎再验一次。

1. 安装本 App  
2. 打开权限：悬浮窗、无障碍、通知（电池优化按引导处理）  
3. **手动**打开 TikTok 并登录好账号（App 永不做登录）  
4. 在本 App 选好方案档位（cold / normal / active）或自定义参数  
5. 确认真正要执行的模块、概率和上限；关闭的模块绝不执行  
6. 点「显示悬浮窗」，回到 TikTok  

**通过条件：** 权限齐全 + TikTok 已安装 + 无障碍已开。  
**不通过：** 主界面标红，禁止开始，引导去开权限。

---

### 3.3 阶段 1：开场检查（机器，约数秒）

用户点悬浮窗 **开始** 后立刻执行：

| 步骤 | 动作 | 失败怎么处理 |
|------|------|----------------|
| 1.1 | 无障碍是否仍开启 | 停，提示去开无障碍 |
| 1.2 | 悬浮窗是否可用 | 可警告；不影响引擎但操控变差 |
| 1.3 | 是否有网络（系统连通） | 停，提示网络 |
| 1.4 | 拉起或切到 TikTok 前台 | 失败则停 |
| 1.5 | 识别是否在「可浏览」页（优先推荐流） | 若在可恢复页（评论/误入二级页）→ 有限次回首页；若是验证码/登录墙 → **阻断停机** |
| 1.6 | 创建本次任务目录，写入开始事件 | — |
| 1.7 | 初始化预算：剩余时间、剩余条数、互动计数归零 | — |

**结束态：** `READY_TO_WORK`，进入阶段 2 或 3。

---

### 3.4 阶段 2：兴趣搜索段（可选，配置决定）

**目的：** 用关键词把推荐兴趣往 niche 上靠，而不是只傻刷 FYP。

**何时执行：** `search.enabled = true` 且关键词列表非空。  
**何时跳过：** 关闭搜索 → 直接阶段 3。

**固定子流程（每个关键词一轮）：**

```text
取一个关键词（随机或顺序）
  → 打开搜索入口
  → 输入关键词并提交
  → 等待结果页
       ├─ 空结果 → 记事件，换下一关键词（不失败整任务）
       ├─ 未知页 → 快照；按配置 skip 或 整任务阻断
       └─ 有结果 → 点进一条视频，进入「单视频循环」做 N 条
                    （N = videos_per_keyword）
  → 用「回推荐流」固定动作回到 FYP
  → 若未达 max_searches 且还有词 → 下一关键词
  → 否则 → 阶段 3
```

**单视频循环**（搜索段与推荐段共用同一套，见 3.6）。

**预算：** 搜索段同样消耗「总时长」和「总条数」；耗尽则跳过剩余搜索，进收尾。

---

### 3.5 阶段 3：推荐流主段（核心，必做）

**目的：** 会话的主要观看与轻互动发生在这里。

```text
while 未超时 and 未达条数上限 and 用户未停止:
    确认仍在推荐流（否则走恢复/阻断）
    执行「单视频循环」
    若还要继续 → 拟人上滑下一条
    视频之间随机停顿
→ 收尾
```

会话编排支持两种模式，二者共用同一套单视频循环、动作模块和安全规则：

- `ordered`：保留原有顺序流程，按 `source_order` 依次运行搜索段和推荐流主段。
- `recommendation_led`：先浏览推荐流；正向兴趣信号达到阈值后，执行一次有上限的单关键词搜索段；回到推荐流并满足冷却条数后，才允许再次触发。搜索词只能来自用户配置的候选列表，不自动生成。

推荐驱动模式不把“相关”直接等同于互动。它只负责内容来源迁移；点赞、收藏、评论、关注、Repost 和不感兴趣仍各自遵守模块开关、概率、相关性条件和会话上限。

---

### 3.6 单视频循环（全流程唯一的「看一条」标准动作）

**固定骨架：**

```text
A. 安全探测
   读当前页状态
   · 阻断类 → 立刻进入「阻断停机」（不做后面步骤）
   · 可逆干扰 → 恢复（有限次）后重读
   · 确认是视频内容页

B. 观看
   在 [watch_min, watch_max] 秒内随机停留
   · 若正向兴趣词命中，可叠加配置的额外观看时长
   （期间不乱点；可记录作者/简介若节点可读）

C. 兴趣判定（若启用了正向兴趣词）
   标题、简介、作者或已读取评论命中正向词后标记为相关，
   供“仅对感兴趣内容”条件和推荐驱动的搜索触发使用

D. 方案动作链（只执行已启用模块）
   按 workflow_order 依次处理：
   · 评论区浏览：打开评论 → 随机停留 → 有限滚动 → 有限展开二级回复 → 返回视频
     可独立设置进入概率，并可限制为仅对符合兴趣的视频执行
   · 点赞 / 收藏 / 评论 / 关注 / Repost：同时满足概率、相关性条件和会话上限才执行一次
   · 不感兴趣：仅在命中独立负向关键词、通过概率且未达会话上限时执行一次
   · 任一写操作结果不明确 → 停止任务，不重试
   · 评论文案只从用户填写的候选池选择，禁止自动生成

E. 落盘并翻页
   写入 videos 明细 + 更新悬浮窗计数
   若预算未耗尽，先按浏览模块参数普通滑动；未换页时依次升级为长距离快速滑动
   每次都比较当前视频指纹，最多三次，仍无法确认则停止
```

固定不可重排：安全探测、观看、兴趣判定、落盘和翻页。自定义方案可交换“兴趣搜索”和“推荐流浏览”的先后；动作链仍在当前视频完成观看后执行。

---

### 3.7 阶段 4：收尾汇总

**触发条件（任一）：**

- 时间预算到  
- 条数预算到  
- 用户点停止  
- 阻断停机  
- 无障碍断开 / TikTok 被杀  
- 不可恢复错误  

**固定动作：**

1. 停止一切新手势  
2. 尽量回到无危险状态（不强制乱点返回）  
3. 写 `summary`（计数、停止原因、是否人工阻断）  
4. 更新悬浮窗与通知：「已结束 / 需人工」  
5. 前台服务可结束或保留到用户确认

## 4. 横切机制（穿插在全流程）

### 4.1 暂停 / 继续 / 停止

| 操作 | 行为 |
|------|------|
| 暂停 | 不再发新手势；计时是否冻结可配置，默认冻结预算时间 |
| 继续 | 从下一拍安全探测接着跑 |
| 停止 | 进入收尾，`stop_reason=user` |
| 紧急停止 | 同停止，UI 更醒目 |

全部只在本机悬浮窗 / 通知栏触发。

### 4.2 阻断 vs 恢复

| 类型 | 例子 | 策略 |
|------|------|------|
| 阻断 | 验证码、登录墙、限流文案、权限弹窗、年龄/隐私确认、未知系统框 | **停**；快照；悬浮窗红态；等人 |
| 可逆 | 误开评论、推广关闭钮、键盘挡住、误入收件箱/个人页 | 白名单动作恢复，**最多 N 次**，每次后重检 |
| 服务异常 | 无障碍被关、TikTok 不在前台且拉不起 | 当阻断处理 |

### 4.3 预算

| 预算 | 规则 |
|------|------|
| 时间 | `max_minutes`，含观看与操作；暂停默认不计入 |
| 条数 | `video_count`，搜索段 + 推荐段合计 |
| 互动上限 | 赞/藏/评/关各自 max_*，达到后本会话不再该类动作 |

先到先停，停止原因写入 summary。

### 4.4 模块授权与单次执行

```text
模块关闭
  → 不进入该动作，不清空已填写参数

模块开启
  → 仍须命中概率、满足相关性条件且未达到 max_* 上限
  → 每条视频最多尝试一次；结果不明确立即停，不重试
```

Android App 不提供预演总开关；是否执行由每个模块自己的启用状态决定。

## 5. 一次完整会话时间线（例子）

**配置：** cold · 20 分钟 · 12 条 · 搜索开 · 2 个词各 2 条 · 点赞模块 15%  

```text
00:00  点悬浮窗开始 → 开场检查通过
00:05  搜索 “technology” → 进视频
00:05–02:00  搜后看 2 条（含评论区）
02:05  回 FYP → 搜索 “programming” → 再 2 条
04:00  进入推荐流主段，继续看到满 12 条或 20 分钟
…      期间悬浮窗显示：已看 x · 步骤「观看/评论」
结束   summary：videos_seen、likes、stop_reason=completed
```

## 6. 档位怎么映射到流程

| | cold | normal | active |
|--|------|--------|--------|
| 搜索段 | 可关或少词 | 开 | 开 |
| 时长 / 条数 | 短 | 中 | 长 |
| 赞/藏/评概率 | 低，评多为 0 | 中 | 较高仍封顶 |
| 关注 | 关 | 可选 | 可选 |
| 内置动作顺序 | 评论区→点赞→收藏→评论→关注→转发→不感兴趣 | 点赞→评论区→收藏→关注→评论→转发→不感兴趣 | 点赞→收藏→评论区→关注→评论→转发→不感兴趣 |

表中只表示排序；实际流程会跳过未启用模块。自定义方案沿用当前参数，并允许用户用上下按钮调整已启用动作的先后顺序。

## 7. 功能清单（按模块，便于实现）

### 7.1 本机 App 壳

- 主界面：权限体检、配置、历史  
- 前台服务 + 通知（暂停/停止）  
- 本地存储：方案、任务目录、summary  
- **无服务端、无远程下发**

### 7.2 悬浮窗

- 收起小圆球 / 展开面板、拖动记位置  
- 开始 · 暂停/继续 · 停止  
- 状态色：空闲 / 运行 / 暂停 / 阻断  
- 实时：已看、用时、步骤、互动计数  

### 7.3 引擎（固定骨架 + 动作工作流）

- 阶段 0～4 按本文第 3 节实现，不得绕过安全检查和收尾  
- 单视频固定执行 A 安全探测、B 观看、C 兴趣判定、E 落盘翻页；D 动作链按方案顺序执行  
- 预算、暂停、阻断、恢复横切  

### 7.4 自动化能力

- 无障碍：节点查找、点击、滑动、输入  
- TikTok：搜索、回 FYP、评论开关、赞/藏/评/关/转发/不感兴趣  
- 页面与阻断识别  

### 7.5 日志

- 每次任务目录  
- 明细 + 事件 + summary  
- 阻断快照（节点树/截图，能力允许时）

## 8. 配置字段（与流程绑定）

```yaml
profile: cold                 # 只影响默认数值

source_order: [search, feed]  # 自定义方案可交换兴趣搜索与推荐流浏览

journey:
  mode: ordered                # ordered | recommendation_led
  bootstrap_feed_videos: 3     # 推荐驱动：首次搜索前至少浏览的推荐视频
  signal_hits: 2               # 推荐驱动：触发搜索所需正向兴趣命中数
  search_cooldown_feed_videos: 5 # 推荐驱动：两次搜索间至少浏览的推荐视频

workflow_order:              # 自定义方案可重排；未启用模块会跳过
  [comments, like, favorite, comment, follow, share, not_interested]

session:
  max_minutes: 20
  video_count: 12
  seed: null                  # 可选，复现随机

search:
  enabled: true               # false → 跳过阶段 2
  keywords: [technology, programming]
  pick: random                # random | sequential
  max_searches: 3
  videos_per_keyword: 2

browse:
  watch_seconds: [8, 20]
  open_comments: true
  comment_rate: 1.0
  comments_only_if_relevant: false
  comment_seconds: [2, 6]
  comment_scrolls: 1
  reply_threads: 1
  auto_recover: true
  max_recovery_actions: 3

interest:
  enabled: false
  keywords: [technology, programming]
  extra_watch_seconds: [0, 0]

not_interested:
  enabled: false
  keywords: [广告, 搬运]
  rate: 0.5
  max: 3

interactions:
  like_enabled: true
  like_rate: 0.15
  favorite_enabled: true
  favorite_rate: 0.05
  comment_enabled: false
  comment_rate: 0.0
  comment_texts: []
  comment_order: random
  max_likes: 3
  max_favorites: 2
  max_comments: 1

follow:
  enabled: false
  rate: 0.05
  max_follows: 1
  only_if_relevant: true

share:
  enabled: false             # TikTok Repost 公开转发；不选择联系人
  rate: 0.02
  max_shares: 1
  only_if_relevant: true

safety:
  stop_on_blockers: true
  require_network: true

overlay:
  start_collapsed: true
  vibrate_on_block: true
```

- [ ] 配置与日志只在本机

## 11. 实现时注意

1. **流程代码集中在一个引擎状态机**，配置注入参数和动作顺序，避免每个功能各自乱跳页。
