# RPA-TT 第一阶段设计

## 目标

在一台已登录 TikTok 的 Android 真机上，建立可审计、可停止、可逐步扩展的
本地 RPA。第一阶段验证设备连接、应用启动、截图和 UI 层级读取；后续再加入
搜索和浏览状态机。

## 借鉴的产品流程

TikMatrix 展示了一个合理的产品分层：设备管理、任务配置、任务执行、运行日志。
本项目只借鉴这套流程，不复制其源码，也不依赖其闭源 Agent：

```text
CLI/后续控制台
    -> 任务配置
    -> Python 状态机
    -> uiautomator2
    -> ADB
    -> Android 真机上的 TikTok
```

## 模块边界

### Android 本机应用

- `runtime/WarmupSessionController`：实际任务功能入口，封装配置读取以及任务的启动、暂停、停止和状态订阅；不依赖悬浮窗。
- `engine/`、`automation/`、`storage/`：状态机、TikTok 页面操作与运行日志，是实际功能实现。
- `overlay/OverlayState`、`OverlayActions`、`FloatingOverlayController`：纯悬浮窗 UI 模块，只渲染 UI 状态并发出用户命令；不引用任务引擎或配置。
- `service/WarmupForegroundService`：Android 生命周期组合层，连接运行模块、悬浮窗和通知栏，不承载任务业务逻辑。
- `service/RunUiStateMapper`：把运行状态显式转换成悬浮窗状态，阻止 UI 模型反向渗入执行模块。

### 界面与悬浮控制

- 应用主题基于官方 Material Components 的 Material 3 深色主题；按钮、卡片、复选框、文本输入框、进度环与对话框使用对应的 Material 组件。
- 首页顶部的无障碍、悬浮窗和 TikTok 三项状态等宽居中；应用权限不属于任务方案，统一进入独立的“应用设置”二级页。
- 方案编辑页按“预算 + 执行顺序 + 独立执行模块”组织。浏览与滑动是每条视频的固定起点，保存记录与翻页是固定收尾；其余互动模块各自拥有启用开关、摘要、折叠参数区和持久化配置，展开一个模块时自动收起其他模块。
- 独立模块包括兴趣搜索、评论区浏览、点赞、收藏、评论、关注、转发、不感兴趣、安全与恢复；关闭模块只停止执行，不清空已经填写的参数。
- 轻量、常规、积极会加载不同的预算、互动概率和固定执行顺序；自定义方案可用上下按钮重排已启用的中间动作，保存后首页顺序预览和执行引擎同时刷新。
- 兴趣搜索属于会话前置阶段，只在启用时显示为执行链第一步，不再作为首页孤立的关键词入口。
- 悬浮球收起态保持 48dp 触控目标；展开态为 72dp × 250dp 的双页纵向侧栏。
- 第一页是任务控制，第二页是方案与 App 入口；向上滑进入第二页，向下滑回第一面。
- 翻页使用 Material Shared Axis Y（纵向共享轴）过渡，持续 260ms；页码点垂直排列并跟随当前页更新。
- 悬浮窗只发出开始、暂停、停止、选择方案和打开 App 命令，不直接承载任务业务逻辑。

依赖方向固定为：`service -> runtime`、`service -> overlay`，`runtime` 与 `overlay` 互不依赖。

### Python 探索工具

- `device.py`：连接设备，读取设备、Android 有效网络和应用状态；只读 UI 层级瞬断时有限重试。
- `state.py`：统一识别页面、内容类型、能力、警告和阻断状态。
- `recovery.py`：按任务上下文规划并执行可逆恢复，每次动作后重新检测。
- `tiktok.py`：TikTok 生命周期及后续页面状态机。
- `artifacts.py`：为截图、UI XML 和日志创建本地运行目录。
- `cli.py`：面向用户的命令入口。

## 安全边界

- 不清除 TikTok 数据，不退出或切换账号。
- 不自动注册账号，不处理验证码和登录挑战。
- Android App 不再提供预演模式；每个写操作必须同时满足“模块已开启、概率命中、相关性条件和单次上限”才会执行。
- 评论只从用户明确填写的候选文案中选择，不自动生成；发送结果不明确时停止且不重试。
- 点赞、收藏、评论、关注和转发各自拥有概率、相关性条件与单次会话上限；转发固定采用 TikTok Repost，并在分享面板中复核撤销入口。
- 任何写操作结果不明确时立即停止，不自动重复点击。
- 页面状态不符合预期时停止，并保留截图及 UI XML。
- 检测到验证码、登录挑战或 TikTok 离开前台时立即停止。
- 检测到断网、频率限制、内容不可用、权限、更新、年龄或账号限制时也立即停止。
- 自动恢复仅处理已知可逆干扰；隐私确认、验证码和未知系统弹窗必须人工处理。
- 缓存视频不作为联网证据；Android 必须存在 `VALIDATED` 的 Wi-Fi、蜂窝、以太网或蓝牙网络。
- 个人页、商城、搜索页、设置、内容偏好和收件箱只在任务目标为推荐页时返回首页。
- UIAutomator 读取失败可重启服务并最多重试三次；点击、评论及其他写操作不自动重试。
- 视频停留、评论停留、评论滑动和视频翻页使用明确的可配置区间。
- 单次滑动由多段触点构成，在快速 flick、普通 swipe、慢速 drag 三类轨迹间选择。
- 评论区识别“查看若干条回复”，有限展开二级评论后再继续滚动。
- 单次会话有最长时间限制；节奏变化是负载控制，不承诺规避平台风控。
- 所有运行产物只保存在本机 `runtime/`。
- 搜索提交状态与搜索内容状态分开记录；明确的空结果不等于自动化执行失败。

## 后续里程碑

1. 持续从真实截图和 UI XML 扩充不同语言及 TikTok 版本的异常页定位器。
2. 实现“搜索关键词 -> 打开结果 -> 浏览限定条数 -> 返回首页 -> 结束”。
3. 增加任务时长、关键词、浏览条数和停止条件配置。
4. 增加 SQLite 运行记录及可视化控制台。
