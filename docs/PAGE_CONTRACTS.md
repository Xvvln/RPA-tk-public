# 页面契约与状态迁移

页面识别不得由单个节点命中直接决定。分类器输出 `page`、`confidence` 和
`evidence`，执行器还必须用连续两次快照及最近动作验证状态迁移。

控件定位同样不得由短资源 ID 单独决定。业务层只请求语义角色，统一解析器综合：

- 可见性、前台包名和控件类型；
- 文本或无障碍描述；
- 屏幕区域和相邻控件几何关系；
- Accessibility window、共同父容器或祖先；
- 语义节点与动作节点可以分离：子节点证明控件角色，最近的可见可点击祖先负责执行；
- 当前页面契约和动作后的状态变化；
- 已知资源 ID 仅作为低权重加分证据。

候选分数不足或前两名过于接近时不点击，返回未知控件并停止写操作。
历史阻断快照的回放审计会检查画面中实际出现的全部动作角色，包括点赞、评论、收藏、
分享和关注；不能只验证当前报错的单个角色。

文字输入采用一次性事务：写入前绑定 window、树路径和几何位置；写入动作只执行一次；
键盘导致页面重排时仍按原节点身份复核，不以新出现的空白克隆框否定结果。草稿确认后，
仅在检测到输入法窗口时收起键盘，再重新解析可见输入框与发送按钮，并在发送前核对草稿。

已通过契约解析的动作控件优先使用 Accessibility window 与树路径定位实时节点并执行；
若节点不支持无障碍动作，才点击其屏幕可见交集区域。底部被裁切的评论发送按钮不再按越界
中心点点击。任何清理草稿、关闭面板或返回操作之前，先保存原始节点树和截图，避免恢复动作
覆盖真正的失败现场。

菜单文字与状态复核只读取当前 TikTok 窗口中的可见节点，禁止用保留的离屏节点证明关注、
转发或“不感兴趣”成功。关注按钮消失必须在同一视频上连续稳定出现；转发和负向反馈在
关闭面板前保存复核现场，结果不明确时不重复执行。

## 评论面板契约

以下必要证据必须同时成立：

1. 可见的评论标题；
2. 可见的评论列表或评论文本容器；
3. 可见且中心位于屏幕下半区的评论输入框；
4. 三类节点位于同一 Accessibility window，并共享评论抽屉内部的树祖先；
5. 当前不存在“搜索框 + 搜索结果容器/卡片”的强反向证据。

关闭按钮只是辅助证据，不能独立或与输入框组合成评论页。评论输入框残留、树外节点、
不可见节点都不满足契约。

## 其他核心契约

- `FEED`：至少两个可见的视频动作栏锚点；搜索视频可保留顶部搜索框，但不能同时出现搜索结果容器。
- `SEARCH_INPUT`：可见搜索输入框和可见提交按钮，且没有视频动作栏或完整评论面板。
- `SEARCH_RESULTS`：可见搜索输入框，以及可见结果容器或结果卡片。
- `SEARCH_EMPTY`：可见搜索输入框及明确的无结果提示。
- 多个契约分数接近、证据不足或冲突时返回 `UNKNOWN`。

## 稳定性与迁移

- 进入可操作状态前至少连续采样两次；页面相同且两次置信度均不低于阈值才算稳定。
- `FEED -> COMMENTS` 只允许发生在 `OPEN_COMMENTS` 动作之后。
- `COMMENTS -> FEED` 只允许发生在关闭评论面板之后。
- 搜索入口、提交搜索、打开结果视频也各自使用显式动作约束。
- 非预期迁移、低置信度和不稳定快照一律变为 `UNKNOWN`，停止写操作并按有限策略处理。
